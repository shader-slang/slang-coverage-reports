      15                         : // `specializeResourceSelections` eliminates IR operations that conditionally compute resources.
      16                         : // When the possible resources come from different bindings, we branch around each operation that
      17                         : // uses the chosen resource instead. Consider this example:
      18                         : //
      19                         : //     Texture2D<float4> first, second;
      20                         : //     SamplerState sampler;
      21                         : //     float4 sampleSelectedTexture(bool condition, float2 uv)
      22                         : //     {
      23                         : //         Texture2D<float4> texture = condition ? first : second;
      24                         : //         return texture.Sample(sampler, uv);
      25                         : //     }
      26                         : //
      27                         : // For this function, `specializeResourceSelections` branches on `condition`: one branch samples
      28                         : // `first`, and the other samples `second`. We merge the `float4` sample result instead of a
      29                         : // texture. If invocations in a derivative group take different branches, each sample may lack the
      30                         : // peers needed to compute implicit derivatives. We warn about that possibility without preventing
      31                         : // the resource transformation. Explicit-LOD samples, explicit-gradient samples, and recognized
      32                         : // per-invocation resource accesses do not require a derivative warning. To choose the diagnostic,
      33                         : // we classify the IR and SPIR-V instructions that will execute conditionally and follow direct
      34                         : // calls into their function bodies. Any recognized derivative requirement warrants the derivative
      35                         : // warning, even if another operation is unknown. Otherwise, an unrecognized instruction or
      36                         : // unavailable callee leaves the participation requirement unknown and warrants a separate warning.

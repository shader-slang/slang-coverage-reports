       7                         : // A note on row/column "terminology reversal".
       8                         : //
       9                         : // This is an "terminology reversing" implementation in the sense that
      10                         : // * "column" in Slang code maps to "row" in the generated WGSL code, and
      11                         : // * "row" in Slang code maps to "column" in the generated WGSL code.
      12                         : //
      13                         : // This means that matrices in Slang code end up getting translated to
      14                         : // matrices that actually represent the transpose of what the Slang matrix
      15                         : // represented.
      16                         : // Both API's adopt the standard matrix multiplication convention whereby the
      17                         : // column count of the matrix on the left hand side needs to match row count of
      18                         : // the matrix on the right hand side.
      19                         : // For these reasons, and due to the fact that (M_1 ... M_n)^T = M_n^T ... M_1^T,
      20                         : // the order of matrix (and vector-matrix products) products must also reversed
      21                         : // in the WGSL code.
      22                         : //
      23                         : // This may lead to confusion (which is why this note is referenced in several
      24                         : // places), but the benefit of doing this is that the generated WGSL code is
      25                         : // simpler to generate and should be faster to compile.
      26                         : // A "terminology preserving" implementation would have to generate lots of
      27                         : // 'transpose' calls, or else perform more complicated transformations that
      28                         : // end up duplicating expressions many times.

 886// Decides whether a call can fail to return to its caller, so that
 887// coverage coalescing knows when a straight-line run of markers is
 888// really straight-line.
 889//
 890// Coalescing replaces several line markers with a single probe, which
 891// is only sound when reaching the probe proves every marker it stands
 892// for also executed. Inside one basic block that holds automatically
 893// for ordinary code, because a block has a single entry and a single
 894// exit. It stops holding when an instruction in the middle of the
 895// block can abandon the invocation, since the instructions after it
 896// then execute fewer times than the ones before it. Consider:
 897//
 898//     void maybeKill(float v) { if (v < 0.5f) discard; }
 899//
 900//     float4 main(float2 uv : TEXCOORD) : SV_Target
 901//     {
 902//         float a = uv.x + 1.0f;   // marker 1
 903//         maybeKill(a);            // marker 2
 904//         float c = a + 3.0f;      // marker 3
 905//         return float4(c);        // marker 4
 906//     }
 907//
 908// All four markers sit in `main`'s entry block, but when `maybeKill`
 909// discards, markers 1 and 2 have executed and markers 3 and 4 have
 910// not. Coalescing all four onto one counter would misreport one side
 911// or the other, so the run must be split at the call.
 912//
 913// Results are memoized per function, and the analysis is a depth-first
 914// walk of the call graph — not an iterated fixpoint — so an exit deep in
 915// a callee still splits the caller's run. Cycles are broken by reporting
 916// the re-entered function as possibly not returning, which keeps the
 917// walk terminating without letting an optimistic answer escape into
 918// other functions' cached results.
 919//
 920// Known gap: any core-module intrinsic that abandons the invocation —
 921// the ray-tracing hit terminators `IgnoreHit` and `AcceptHitAndEndSearch`
 922// are the concrete examples today — lowers to a `GenericAsm` terminator
 923// like every other intrinsic, and `mayNotReturn` treats `GenericAsm` as
 924// a normal exit (see the comment on that case below). So this is not a
 925// gap specific to those two names: it is general to any present or
 926// future abandoning intrinsic modeled the same way. Slang's IR has no
 927// `[noreturn]` concept to key off instead. Marking them in the
 928// core module is the principled fix and is tracked separately.
 929// Returns true when every block reachable from `func`'s entry can still
 930// reach a normal exit — an `IRReturn`, or an `IRGenericAsm`, which is how
 931// `__intrinsic_asm` lowers and which ends the function the same way.
 932//

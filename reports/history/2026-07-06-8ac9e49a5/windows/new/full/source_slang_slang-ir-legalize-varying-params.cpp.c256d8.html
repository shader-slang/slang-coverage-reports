      43              : //
      44              : // The traditional Slang/HLSL model is to have varying input parameters
      45              : // be marked with "semantics" that can either mark them as user-defined

      47              : // of the function can be marked, and effectively works like an `out`
      48              : // parameter.
      49              : //
      50              : // Other targets have very different models for how varying parameters
      51              : // are passed:
      52              : //
      53              : // * GLSL/SPIR-V declare user-defined varying input/output as global variables,
      54              : //   and system-defined varying parameters are available as magic built-in variables.
      55              : //
      56              : // * CUDA compute kernels expose varying inputs as magic built-in

      60              : //   that specifies the values of the critical varying parameters for compute shaders.
      61              : //

      63              : // they share the common theme that they cannot work with the varying parameter
      64              : // signature of functions as written in vanilla HLSL.

      71              : //

      73              : //   entry point to be used interchangeably, so ensuring both cases are treated

      77              : //   we need to recursively process elements and/or fields to find the leaf

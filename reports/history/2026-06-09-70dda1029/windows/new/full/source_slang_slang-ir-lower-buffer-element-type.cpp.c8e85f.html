       9              : /// This file implements an important IR transformation pass in the Slang compiler
      10              : /// that rewrites buffer element types into valid storage types, a.k.a physical types
      11              : /// in SPIRV terminology.
      12              : ///
      13              : /// Many of our targets have special restrictions on what is allowed to be used as a
      14              : /// buffer element. Examples are:
      15              : /// - In SPIRV, `bool` is considered a logical type, meaning it cannot appear inside
      16              : ///   buffers. bool vectors and matrices needs to be lowered into arrays.
      17              : /// - In SPIRV, if `T` is used to declare a buffer, then every member in `T` must have
      18              : ///   explicit offset. But if it is used to declare a local variable, then it cannot
      19              : ///   have explicit member offset. This means that we cannot use the same `Foo` struct
      20              : ///   inside a `StructuredBuffer<Foo>` and also use it to declare a local variable.
      21              : /// - In Metal, if we have a `struct Foo {Texture2D member; }` and
      22              : ///   `ParameterBlock<Foo>`, then we should translate it to
      23              : ///   `struct Foo_pb { Texture2D.Handle member; }` and `ParameterBlock<Foo_pb>`, so that
      24              : ///    the resource legalization pass won't hoist the texture out of the parameter block.
      25              : /// - In Metal, pointer types in buffer pointee types are lowered to UIntPtr:
      26              : ///   all pointers in storage buffers (the buffer itself adds a level of
      27              : ///   indirection), and multi-level pointers (e.g. `int**`) in all buffer
      28              : ///   kinds. This runs as a separate late invocation so that address-space
      29              : ///   specialization sees real pointer types.
      30              : ///
      31              : /// We use the terms "physical", "storage", or "lowered" types to refer to types that
      32              : /// are legal to use as buffer elements. In contrast, the terms "original" or "logical"
      33              : /// refers to types that are declared by the user in its original form.
      34              : /// For example, `bool4` is a "logical" type, and its lowered type is `int4`.
      35              : ///
      36              : ///
      37              : /// # Algorithm Overview
      38              : /// ----------------------
      39              : ///
      40              : /// This pass performs the transformation to create one "storage" type for each type that
      41              : /// are used in each kind of buffer. For example, if user defined `Foo`, and used it in
      42              : /// `ConstantBuffer<Foo>` and `StructuredBuffer<Foo>` and is targeting SPIRV, this pass will
      43              : /// create `Foo_std140` and `Foo_std430` types, and update the buffer to be
      44              : /// `ConstantBuffer<Foo_std140>` and `StructuredBuffer<Foo_std430>`.
      45              : ///
      46              : /// The pass will rewrite all the code that uses this buffers, and insert translations between
      47              : /// Foo_std140/Foo_std430 and Foo to keep types consistent.
      48              : ///
      49              : /// For example, given:
      50              : /// ```
      51              : /// struct Foo {
      52              : ///     bool4x4 v;
      53              : /// }
      54              : /// ConstantBuffer<Foo> cb;
      55              : /// bool test(Foo f) {
      56              : ///     return f.v[0][1];
      57              : /// }
      58              : /// void main() { test(cb); }
      59              : /// ```
      60              : ///
      61              : /// This pass will rewrite it as:
      62              : /// ```
      63              : /// struct Foo {
      64              : ///     bool4x4 v;
      65              : /// }
      66              : /// struct Foo_std140 {
      67              : ///     Matrix_bool4x4_std140 v;
      68              : /// };
      69              : /// struct Matrix_bool4x4_std140 {
      70              : ///     int4 values[4];
      71              : /// };
      72              : /// ConstantBuffer<Foo_std140> cb;
      73              : /// bool test_1(Foo_std140 f) {
      74              : ///     return f.v.values[0][1];
      75              : /// }
      76              : /// void main() { test_1(cb); }
      77              : /// ```
      78              : ///
      79              : /// Note that the one important optimization here is we will defer the translation from
      80              : /// storage type to logical type at latest possible time. In the example above, we could
      81              : /// have loaded `cb` and then immediately translate it into `Foo` and call `test` with
      82              : /// the translated value. However that can lead to code that create unnecessary copies
      83              : /// that can't always be removed by the downstream compiler, particulary if there are
      84              : /// arrays whose element type needs non-trivial translation.
      85              : ///
      86              : /// To avoid the performance issue, we will defer this translation until a logical value
      87              : /// is actually needed. This is done by pushing the translation to the use sites, and
      88              : /// across function call boundaries, specializing any functions being called along the
      89              : /// chain. This case, since we are calling `test()` from `main()` with `Foo_std140`, instead
      90              : /// of converting the `Foo_std140` to `Foo` before the call, we create a specialization
      91              : /// of `test` that accepts `Foo_std140` instead.
      92              : ///
      93              : /// To enable this interprecedural transformation, the pass is organized as two phases:
      94              : /// 1. Create lowered / storage types for all buffer element types, and update
      95              : ///    global buffer declarations to use storage types. This is implemented in `processModule()`
      96              : /// 2. Insert a `CastStorageToLogical(loweredBuffer)` inst, and replace all uses of
      97              : ///    `loweredBuffer` with the cast inst. This is implemented in `processModule()`
      98              : /// 3. Push the `CastStorageToLogical` insts to as late as possible, which means if we see
      99              : ///    `FieldAddress(CastStorageToLogical(storageAddr), memberKey)`, we should translate
     100              : ///    it into `CastStorageToLogical(FieldAddress(storageAddr, memberKey)`.
     101              : ///    If we see a `CastStorageToLogical` inst being used as argument to call a function `f`,
     102              : ///    specialize `f` to take a pointer to the storage type instead, and insert a
     103              : ///    `CastStorageToLogical(param)` to convert the param type to logical type at the
     104              : ///    beginning of the specialized function. (implemented in `deferStorageToLogicalCasts()`)
     105              : ///
     106              : /// Repeat step 2 and 3 until no more changes can be made, then proceed to step 4.
     107              : ///
     108              : /// 4. Materialize all remaining `CastStorageToLogical(addr)` by replacing all `load` of such
     109              : ///    cast insts with `call unpackStorage(addr)`, where `unpackStorage` is a function we
     110              : ///    synthesize that reads from an address of a storage type and returns a logical type;
     111              : ///    and replacing all `store(CastStorageToLogical(addr), value)` with `packStorage(addr, value)`,
     112              : ///    where `packStorage` is a function we synthesis that writes a logical value into a storage
     113              : ///    addr. This is implemented in `materializeStorageToLogicalCasts()`.
     114              : ///
     115              : /// That's the main idea of the pass.
     116              : ///
     117              : /// # Propagating through SSA values
     118              : ///
     119              : /// Note that `kIROp_CastStorageToLogical` is a pseudo instruction introduced in this pass that
     120              : /// has the semantics of "converting a pointer to a storage value into a pointer to a logical
     121              : /// value". A dual of this inst is `kIROp_CastStorageToLogicalDeref`, which has an additional
     122              : /// builtin "load" semantic. That is, given `Ptr<StorageType> addr`, `CastStorageToLogical(addr)`
     123              : /// will have type `Ptr<LogicalType>`, and `CastStorageToLogicalDeref(addr)` will have type
     124              : /// `LogicalType`. In other words, `CastStorageToLogicalDeref(addr)` is equivalent to
     125              : /// `load(CastStorageToLogical(addr))`.
     126              : ///
     127              : /// The `CastStorageToLogicalDeref` pseudo inst is needed to push defer through `load`s.
     128              : /// Consider the following example:
     129              : /// ```
     130              : ///    ptr : StorageType* = ...
     131              : ///    lptr : LogicalType* = CastStorageToLogical(ptr);
     132              : ///    l = load(lptr)
     133              : ///    m = fieldExtract(l, member)
     134              : ///    call f, m
     135              : /// ```
     136              : /// In this case, only l.member is used, so we should avoid translating other unrelated members
     137              : /// from storage type to logical type. To achieve this we must be able to push the
     138              : /// `CastStorageToLogical` operation beyond the `load`. The steps to achieve this are:
     139              : /// 1. we process `lptr` inst by inspecting its users. We find that a `load` (l) uses it.
     140              : /// 2. replace the `load` with `CastStorageToLogicalDeref(ptr)`, the IR become:
     141              : /// ```
     142              : ///    ptr : StorageType* = ...
     143              : ///    l_1 = CastStorageToLogicalDeref(ptr);
     144              : ///    m = fieldExtract(l_1, member);
     145              : ///    call f, m
     146              : /// ```
     147              : /// 3. push the new `l_1` inst to worklist, and when it gets processed, we continue to inspect
     148              : ///    its users, and find that it is being used by `fieldExtract`. We will rewrite the
     149              : ///    `fieldExtract` into `CastStorageToLogicalDeref(fieldAddr(ptr, member))`, and the IR become:
     150              : ///    ```
     151              : ///       ptr : StorageType* = ...
     152              : ///       m_ptr = FieldAddr(ptr, member)
     153              : ///       m = CastStorageToLogicalDeref(m_ptr);
     154              : ///       call f, m
     155              : ///    ```
     156              : /// 4. Since there are no more uses of `m` that can be translated, stop. Note that it is possible
     157              : ///    to continue specializing `f` and replace its first parameter's type to storage type. However
     158              : ///    this implementation currently does not specialize functions whose parameter type is not a
     159              : ///    pointer/reference type. When we target SPIRV, we will already be running the
     160              : ///    `transformParamsToConstRef` pass that would have converted `f` to take in `ConstRef<T>`.
     161              : ///    In this case, the initial IR would be in the form of
     162              : ///    ```
     163              : ///       ptr : StorageType* = ...
     164              : ///       lptr : LogicalType* = CastStorageToLogical(ptr);
     165              : ///       l = load(lptr)
     166              : ///       m = fieldExtract(l, member)
     167              : ///       var tmpVar : MemberLogiocalType  [[ImmutableTempVar]]
     168              : ///       store tmpVar, m
     169              : ///       call f, tmpVar
     170              : ///    ```
     171              : ///    To allow us to remove the `tmpVar` store introduced during `transformParamsToConstRef`,
     172              : ///    this pass also handles the propagation through temp var stores. After pushing the cast
     173              : ///    through `m`, we will get IR to this form:
     174              : ///    ```
     175              : ///       ptr : StorageType* = ...
     176              : ///       m_ptr = FieldAddr(ptr, member)
     177              : ///       m = CastStorageToLogicalDeref(m_ptr);
     178              : ///       var tmpVar : MemberLogiocalType  [[ImmutableTempVar]]
     179              : ///       store tmpVar, m
     180              : ///       call f, tmpVar
     181              : ///    ```
     182              : ///    This time, we will see that `m` is being used by a `store` into a `[[ImmutableTempVar]]` var,
     183              : ///    and we can safely replace all uses of `tmpVar` to `m_ptr`, and therefore the IR will become:
     184              : ///    ```
     185              : ///       ptr : StorageType* = ...
     186              : ///       m_ptr = FieldAddr(ptr, member)
     187              : ///       m = CastStorageToLogical(m_ptr);
     188              : ///       call f, m_ptr
     189              : ///    ```
     190              : ///    Now, we are in the case where a `CastStorageToLogical` is used as argument in a `call`.
     191              : ///    This will trigger our function specialization rule to create `f_1` that accepets a
     192              : ///    `StorageMember*`, and we will rewrite the IR again to:
     193              : ///    ```
     194              : ///       ptr : StorageType* = ...
     195              : ///       m_ptr = FieldAddr(ptr, member)
     196              : ///       call f_1, m_ptr
     197              : ///    ```
     198              : ///    Note that it is only correct to defer a load/CastStorageToLogicalDeref if the location
     199              : ///    being loaded from is immutable. Otherwise, we might be changing the order of memory
     200              : ///    operations and result in a change in application behavior. So this pass will also make sure
     201              : ///    that we only create `CastStorageToLogicalDeref(x)` such that `x` is an immutable location,
     202              : ///    such as an immutable temporary variable.
     203              : ///
     204              : /// # Trailing Pointer Rewrite
     205              : ///
     206              : /// Another transformation done in this pass is it also rewrites struct with unsized trailing
     207              : /// arrays. Since an unsized type isn't a physical type and cannot be used as a pointee type,
     208              : /// we will have problem translating the following code to SPIRV:

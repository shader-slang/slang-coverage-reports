       3                         : // Classic jump-threading (a CFG optimization -- unrelated to GPU threads/lanes)
       4                         : // for a `switch` whose selector is proven constant on every incoming edge.
       5                         : //
       6                         : // Consider an `if/else-if` ladder that selects a constant integer tag, feeding a
       7                         : // later `switch`:
       8                         : //
       9                         : //     int selected;
      10                         : //     if      (target < c0) selected = 0;
      11                         : //     else if (target < c1) selected = 1;
      12                         : //     else                  selected = 2;
      13                         : //     switch (selected) { case 0: ...; case 1: ...; case 2: ...; }
      14                         : //
      15                         : // In SSA this lowers to a *chain* of single-parameter merge blocks: each nested
      16                         : // `if`'s merge block forwards the running tag one hop outward, ending at the
      17                         : // block whose terminator is the `switch` (the "switch header"). So the selector
      18                         : // is not a single N-predecessor phi but the tail of a forwarding chain:
      19                         : //
      20                         : //     A0: br H2(0)        // arm selecting 0
      21                         : //     A1: br H1(1)        // arm selecting 1
      22                         : //     H1(p1): br H2(p1)   // forwarding merge
      23                         : //     A2: br H2(2)        // arm selecting 2
      24                         : //     H2(p2): switch(p2) [case 0: C0, case 1: C1, case 2: C2] break: M
      25                         : //     C0: br M(r0)   C1: br M(r1)   C2: br M(r2)
      26                         : //     M(result): ...continuation...
      27                         : //
      28                         : // Because each arm proves exactly one case, the runtime `switch` is redundant.
      29                         : // The key observation is that the "fused" spelling (dispatching concretely in
      30                         : // each arm) has the *same chain topology* carrying the case result instead of
      31                         : // the tag. So this pass re-uses the existing chain rather than cloning anything:
      32                         : // it splices each case body into the arm that proves its tag and re-types the
      33                         : // chain to forward results. After the rewrite the example above becomes
      34                         : //
      35                         : //     A0: br C0    A1: br C1    A2: br C2   // arms enter case bodies directly
      36                         : //     C0: br H2(r0)   C1: br H2(r1)   C2: br H2(r2)
      37                         : //     H1(p1): br H2(p1)   // now forwards a result
      38                         : //     H2(p2): br M(p2)    // switch replaced by a plain branch
      39                         : //     M(result): ...continuation...
      40                         : //
      41                         : // which the later CFG cleanup collapses to the fused shape. The transform is
      42                         : // decomposed as prove-then-apply: `tryPlanSwitchThreading` mutates nothing and
      43                         : // assembles a plan only if every safety gate passes; `applySwitchThreading`

       4                         : // This file provides the core services for creating
       5                         : // and solving constraint systems during semantic checking.
       6                         : //
       7                         : // We currently use constraint systems primarily to solve
       8                         : // for the implied values to use for generic parameters when a
       9                         : // generic declaration is being applied without explicit
      10                         : // generic arguments.
      11                         : //
      12                         : // Conceptually, our constraint-solving strategy starts by
      13                         : // trying to "unify" the actual argument types to a call
      14                         : // with the parameter types of the callee (which may mention
      15                         : // generic parameters). E.g., if we have a situation like:
      16                         : //
      17                         : //      void doIt<T>(T a, vector<T,3> b);
      18                         : //
      19                         : //      int x, y;
      20                         : //      ...
      21                         : //      doIt(x, y);
      22                         : //
      23                         : // then an we would try to unify the type of the argument
      24                         : // `x` (which is `int`) with the type of the parameter `a`
      25                         : // (which is `T`). Attempting to unify a concrete type
      26                         : // and a generic type parameter would (in the simplest case)
      27                         : // give rise to a constraint that, e.g., `T` must be `int`.
      28                         : //
      29                         : // In our example, unifying `y` and `b` creates a more complex
      30                         : // scenario, because we cannot ever unify `int` with `vector<T,3>`;
      31                         : // there is no possible value of `T` for which those two types
      32                         : // are equivalent.
      33                         : //
      34                         : // So instead of the simpler approach to unification (which
      35                         : // works well for languages without implicit type conversion),
      36                         : // our approach to unification recognizes that scalar types
      37                         : // can be promoted to vectors, and thus tries to unify the
      38                         : // type of `y` with the element type of `b`.
      39                         : //
      40                         : // When it comes time to actually solve the constraints, we
      41                         : // might have seemingly conflicting constraints:
      42                         : //
      43                         : //      void another<U>(U a, U b);
      44                         : //
      45                         : //      float x; int y;
      46                         : //      another(x, y);
      47                         : //
      48                         : // In this case we'd have constraints that `U` must be `int`,
      49                         : // *and* that `U` must be `float`, which is clearly impossible
      50                         : // to satisfy. Instead, our constraints are treated as a kind
      51                         : // of "lower bound" on the type variable, and we combine
      52                         : // those lower bounds using the "join" operation (in the
      53                         : // sense of "meet" and "join" on lattices), which ideally
      54                         : // gives us a type for `U` that all the argument types can
      55                         : // convert to.

 19/** Overview:
 20
 21There needs to be a mechanism where we can easily and quickly track a specific locations in any
 22source file used during a compilation. This is important because that original location is
 23meaningful to the user as it relates to their original source. Thus SourceLoc are used so we can
 24display meaningful and accurate errors/warnings as well as being able to always map generated code
 25locations back to their origins.
 26
 27A 'SourceLoc' along with associated structures (SourceView, SourceFile, SourceMangager) this can
 28pinpoint the location down to the byte across the compilation. This could be achieved by storing for
 29every token and instruction the file, line and column number came from. The SourceLoc is used in
 30lots of places - every AST node, every Token from the lexer, every IRInst - so we really want to
 31make it small. So for this reason we actually encode SourceLoc as a single integer and then use the
 32associated structures when needed to determine what the location actually refers to - the source
 33file, line and column number, or in effect the byte in the original file.
 34
 35Unfortunately there is extra complications. When a source is parsed it's interpretation (in terms of
 36how a piece of source maps to an 'original' file etc) can be overridden - for example by using #line
 37directives. Moreover a single source file can be parsed multiple times. When it's parsed multiple
 38times the interpretation of the mapping (#line directives for example) can change. This is the
 39purpose of the SourceView - it holds the interpretation of a source file for a specific Lex/Parse.
 40
 41Another complication is that not all 'source' comes from SourceFiles, a macro expansion, may
 42generate new 'source' we need to handle this, but also be able to have a SourceLoc map to the
 43expansion unambiguously. This is handled by creating a SourceFile and SourceView that holds only the
 44macro generated specific information.
 45
 46SourceFile - Is the immutable text contents of a file (or perhaps some generated source - say from
 47doing a macro substitution) SourceView - Tracks a single parse of a SourceFile. Each SourceView
 48defines a range of source locations used. If a SourceFile is parsed twice, two SourceViews are
 49created, with unique SourceRanges. This is so that it is possible to tell which specific parse a
 50SourceLoc is from - and so know the right interpretation for that lex/parse.
 51*/

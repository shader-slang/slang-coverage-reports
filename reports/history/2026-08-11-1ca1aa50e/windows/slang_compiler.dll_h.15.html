 0384static inline bool mi_mul_overflow(size_t count, size_t size, size_t* total) {

 0398  else if mi_unlikely(mi_mul_overflow(count, size, total)) {

 404  }

 624/* -------------------------------------------------------------------
 625Encoding/Decoding the free list next pointers
 626
 627This is to protect against buffer overflow exploits where the
 628free list is mutated. Many hardened allocators xor the next pointer `p`
 629with a secret key `k1`, as `p^k1`. This prevents overwriting with known
 630values but might be still too weak: if the attacker can guess
 631the pointer `p` this  can reveal `k1` (since `p^k1^p == k1`).
 632Moreover, if multiple blocks can be read as well, the attacker can
 633xor both as `(p1^k1) ^ (p2^k1) == p1^p2` which may reveal a lot
 634about the pointers (and subsequently `k1`).
 635
 636Instead mimalloc uses an extra key `k2` and encodes as `((p^k2)<<<k1)+k1`.
 637Since these operations are not associative, the above approaches do not
 638work so well any more even if the `p` can be guesstimated. For example,
 639for the read case we can subtract two entries to discard the `+k1` term,
 640but that leads to `((p1^k2)<<<k1) - ((p2^k2)<<<k1)` at best.
 641We include the left-rotation since xor and addition are otherwise linear
 642in the lowest bit. Finally, both keys are unique per page which reduces
 643the re-use of keys by a large factor.
 644
 645We also pass a separate `null` value to be used as `NULL` or otherwise
 646`(k2<<<k1)+k1` would appear (too) often as a sentinel value.
 647------------------------------------------------------------------- */

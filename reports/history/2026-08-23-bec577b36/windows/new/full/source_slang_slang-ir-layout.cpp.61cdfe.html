      11              : // This file implements facilities for computing and caching layout
      12              : // information on IR types.
      13              : //
      14              : // Unlike the AST-level layout system, this code currently only
      15              : // handles the notion of "natural" layout for IR types, which is
      16              : // the layout they use when stored in general-purpose memory
      17              : // without additional constraints.
      18              : //
      19              : // In general, "natural" layout for all targets is assumed to follow
      20              : // the same basic rules:
      21              : //
      22              : // * Scalars are all naturally aligned and have the "obvious" size
      23              : //
      24              : // * Arrays are laid out by separating elements by their "stride" (size rounded up to alignment)
      25              : //
      26              : // * Vectors are laid out as arrays of elements
      27              : //
      28              : // * Matrices are laid out as arrays of rows
      29              : //
      30              : // * Structures are laid out by packing fields in order, placing each field on the "next"
      31              : //   suitably aligned offset. The alignment of a structure is the maximum alignment of
      32              : //   its fields.
      33              : //
      34              : // Right now this file implements a one-size-fits-all version of natural
      35              : // layout that might not be a perfect fit for all targets. In particular
      36              : // this code currently assumes:
      37              : //
      38              : // * The `bool` type is laid out as 4 bytes (equivalent to an `int`)
      39              : //
      40              : // * The size of a structure or array type is *not* rounded up to a multiple
      41              : //   of its alignment. This means that fields may be laid out in
      42              : //   the "tail padding" of previous fields in the same structure. This is
      43              : //   correct behavior for VK/D3D, but does not match the behavior of typical
      44              : //   C/C++ compilers.
      45              : //
      46              : // * All matrices are laid out in row-major order, regardless of any
      47              : //   settings in user code.
      48              : //
      49              : // TODO: Addressing the above issues would require extending this file to somehow
      50              : // get target-specific layout information as an input. One option would be
      51              : // to attach information about "natural" layout on the target to the `IRModuleInst`
      52              : // as a decoration, similar to how an LLVM IR module stores a "layout string."

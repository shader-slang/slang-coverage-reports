       7                         : // This file implements a pass to take code in the Slang IR out out SSA form
       8                         : // by eliminating all "phi nodes."
       9                         : //
      10                         : // The Slang IR does not represent phi operations in the "textbook" way, and
      11                         : // it is important to understand how it *does* represent those operations in
      12                         : // order to understand this pass.
      13                         : //
      14                         : // In a textbook encoding of SSA, a basic block begins with zero or more `phi`
      15                         : // instructions:
      16                         : //
      17                         : //      block B:
      18                         : //          let x = phi(a, b);
      19                         : //          let y = phi(c, d);
      20                         : //          ...
      21                         : //
      22                         : // Each `phi` operation has a number of operands equal to the number of
      23                         : // predecessors of `B`, with one operand corresponding to each predecessor.
      24                         : // Semantically, we usually think of a `phi` as auto-magically selecting between
      25                         : // its operands beased on the control-flow path that was used to arrive at `B`.
      26                         : // Note, however, that all of the `phi` operations at the start of a block must
      27                         : // be understood as executing *simultaneously*, so that if `x` or `y` above was
      28                         : // used as a `phi` operand, they would yield their value from *before* the binding
      29                         : // not after. Oh, and also the operands of `phi` instructions are the *one* place
      30                         : // where the rule about how "defs must dominate uses" isn't upheld.
      31                         : //
      32                         : // Our encoding of the same thing is equivalent, more consistent, and in most ways
      33                         : // easier to understand. A basic block in the Slang IR can have *parameters*,
      34                         : // and a branch to such a block must pass *arguments* for those parameters:
      35                         : //
      36                         : //      block B(x,y):
      37                         : //          ...
      38                         : //
      39                         : //      block M:
      40                         : //          ...
      41                         : //          br B(a, c);
      42                         : //
      43                         : //      block N:
      44                         : //          ...
      45                         : //          br B(b, d);
      46                         : //
      47                         : // Note how in this formulation there is no auto-magical behavior. The relationship
      48                         : // between a predecessor block and the values that `x, y` take on is clear. The
      49                         : // way that `x, y` take on their new values simulataneously is also more apparent
      50                         : // (since it intuitively matches a recursive function call). Further, our IR is
      51                         : // able to follow the "def dominates use" rule more completely.
      52                         : //
      53                         : // With that out of the way, let's dive into the pass itself.
      54                         :
